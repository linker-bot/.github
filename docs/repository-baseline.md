# 仓库基础规范

本规范用于新项目起步和现有项目逐步整理。优先遵循项目已有的有效约定；不为统一外观而改变稳定接口、包名或用户安装路径。

## 每个项目必须具备

- README：用途、项目状态、安装条件、可运行的最小示例、文档入口、反馈方式与许可证。
- LICENSE：保留现有许可；新项目由维护者选择许可并写入仓库。第三方代码和模型保留所需声明。
- 兼容说明：列出实际验证的系统、语言/ROS 版本、设备、固件和连接方式。未验证的组合明确标注。
- 可复现验证入口：说明格式检查、构建和相关测试命令，区分软件、仿真与真实硬件测试。
- 发布记录：发布项目记录版本、变更、兼容影响和升级步骤；尚未发布的项目说明当前状态。
- 贡献与安全入口：可使用组织默认文件；有项目专属流程时在项目中覆盖。

使用 [README 模板](../templates/README.template.md) 和 [兼容说明模板](../templates/compatibility.template.md)。

## 推荐约定

- 新仓库名使用小写和连字符；根据用途命名 SDK、集成、仿真或资产项目，不重命名现有仓库以强行对齐。
- README 默认英文，可提供 `README.zh-CN.md`；现有翻译文件名保留并链接。两种语言覆盖相同的关键操作与限制。
- About 描述写清用途；Topics 只填写实际相关的技术与设备。
- 示例从最小场景开始，说明依赖、输入、预期输出和退出方式。
- API 变更记录在 CHANGELOG；明确版本策略和弃用周期，不默认所有实验项目都已具备稳定 API。
- 硬件示例写明前置检查、运动范围、限位和停止方式，遵循设备说明；普通 CI 仅执行无硬件验证。
- CI 使用最小权限，固定依赖或受控版本；第三方 Actions 优先固定到审核过的提交，并由维护者更新。

## 按项目类型组织

[Python](../reference-layouts/python.md)、[C++](../reference-layouts/cpp.md)、[ROS 2](../reference-layouts/ros2.md) 与 [资产](../reference-layouts/assets.md) 使用不同目录。按实际用途创建目录，不添加仅为占位的空目录。

## 需要单独配置的项目设置

维护者为每个项目设置维护负责人、标签、必要状态检查与分支规则。CODEOWNERS 使用真实且有权限的团队/账号；没有确认负责人前不写占位成员。

组织 `.github` 不会自动分发工作流、LICENSE、CODEOWNERS、Dependabot 配置或分支保护。Issue 表单中的标签也不会自动创建，因此公共表单不预设标签。
