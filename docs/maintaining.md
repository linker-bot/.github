# 上线与维护

## 首次上线

1. 检查中英文主页、SVG 横幅和导航目标；横幅是抽象关节手图案，不是产品结构图。
2. 将已审核内容发布到公开 `linker-bot/.github` 的默认分支。当前文件使用 `main` 链接；默认分支变化时同步更新。
3. GitHub 组织页会读取 `profile/README.md`。由组织所有者在页面中设置置顶仓库；文件本身不能更改置顶或头像。
4. 候选置顶：Python SDK、C++ SDK、ROS 2 SDK、linker-sim、linker-sim-assets，以及经验证的演示/可视化项目。检查维护状态后确定。
5. 在一个没有自定义模板的项目中检查默认 Issue / PR 模板与贡献、安全入口；再核对有自定义模板的项目仍使用自身配置。
6. 确认公开邮箱能够接收和分派社区、安全与行为报告；需要独立渠道时再更新对应文件，不发布未经配置的地址。

## 模板仓库建设

本仓库提供文档模板和目录参考。后续分别创建 Python、ROS 2、C++ 和资产模板仓库，并在 GitHub Settings 中启用 Template repository。

每个模板仓库需要具备真实的最小项目、构建配置、无硬件测试和可通过的 CI。选择项目许可证，替换包名与描述，删除不适用内容，并在干净环境验证后再交付。不要把本仓库直接当作 SDK 项目模板。

通过模板创建的仓库是独立副本。模板升级通过显式 PR 同步；组织默认社区文件则按 GitHub 的回退规则生效。

## 现有项目迁移

先选择 Python SDK 和 ROS 2 SDK 做样板。第一批仅补文档、兼容说明与协作配置；源码目录、包名和安装方式调整另开变更，并验证用户兼容性。

## 日常维护

新增、迁移或归档项目时更新两种语言的导航。修改默认模板时检查各项目的覆盖情况；新增必填项应减少用户不必要的负担。按项目实际变化更新规范，而非要求所有历史仓库一次性重构。

## 验收

- 新访客能从主页找到 Python、ROS 2 与仿真入口。
- 新维护者能用 README 模板和目录参考写清安装、验证和兼容范围。
- 公共表单能收集复现所需信息，安全报告不被导向公开 Issue。
- 本仓库许可证与各项目许可证的边界清楚。
