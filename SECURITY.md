# Security policy

This is the organization default. If the affected repository has its own security policy, follow that policy instead.

## Report a vulnerability privately

Do not publish exploit details, credentials, or sensitive logs in a public issue.

1. If the affected repository offers **Security → Report a vulnerability**, use GitHub's private vulnerability reporting form.
2. Otherwise contact [helloworld@linkerbot.cn](mailto:helloworld@linkerbot.cn), the organization's published contact address, with the subject `Security report: <repository>`. Start with a brief description and request a suitable private channel before sharing highly sensitive material.

Include the repository and affected version/commit, impact, prerequisites, a minimal reproduction if safe to share, and any proposed mitigation. Remove credentials and personal data. Avoid testing against other people's devices or systems.

## Supported versions

Support varies by project. Consult the affected repository's releases and security policy. This default policy does not promise support for every historical version or a fixed response time.

For issues involving unexpected physical movement, stop the hardware test and follow the device's documented safe-stop procedure. Share the relevant model, firmware, and circumstances privately if they expose a vulnerability.
